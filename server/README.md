# 종이비행기 랭킹 서버

게임 화면(정적 웹)과 따로 도는 작은 Node 서버입니다. 랭킹 등록과 조회만 맡습니다.
서버가 없어도 게임은 그대로 동작하고, 그때는 랭킹 화면만 숨겨집니다.

- 추가 의존성 없음: `node:http` 만 씁니다.
- 계산은 화면과 **같은 코드**(`src/core`)를 그대로 가져다 씁니다.

## 실행

```bash
npm install
npm run server                                   # http://localhost:8787, 메모리 저장
DATA_FILE=server/data/ranking.json npm run server  # 파일에 저장(껐다 켜도 유지)
```

확인:

```bash
curl http://localhost:8787/api/health
curl "http://localhost:8787/api/leaderboard?mode=distance&limit=10"
```

화면과 함께 띄울 때는 화면 쪽에 서버 주소를 알려 줍니다.

```bash
VITE_API_URL=http://localhost:8787 npm run dev
```

## 환경 변수

| 이름 | 기본값 | 설명 |
| --- | --- | --- |
| `PORT` | `8787` | 듣는 포트 |
| `HOST` | `0.0.0.0` | 듣는 주소 |
| `DATA_FILE` | (없음) | 랭킹을 저장할 JSON 파일 경로. 없으면 메모리에만 두므로 재시작하면 사라집니다. |
| `CORS_ORIGIN` | `*` | 허용할 화면 출처. 예: `https://plane.example.com`. 쉼표로 여러 개를 적을 수 있습니다. |
| `MAX_QUEUE` | `20` | 동시에 받아 둘 등록 요청 수. 넘으면 503 으로 거절합니다. |

## API

모든 응답은 JSON(UTF-8)입니다. 타입 정의는 `src/core/api.ts` 에 있습니다.

### `GET /api/health`

```json
{ "ok": true, "coreVersion": 2 }
```

`coreVersion` 은 서버가 계산에 쓰는 core 의 물리 판 번호(`PHYSICS_VERSION`)입니다. core 에서 그대로 가져오므로 따로 올릴 필요가 없습니다.

### `POST /api/submit`

요청 본문(최대 8 KB):

```json
{ "code": "P1...", "mode": "distance", "nickname": "영욱" }
```

- `code`: 화면이 `encodeDesign(design, throwIn)` 으로 만든 공유 코드. 던지기 값이 들어 있어야 합니다.
- `mode`: `distance`(거리) 또는 `airtime`(체공 시간).
- `nickname`: 1~16자. 앞뒤 공백과 제어 문자는 서버가 지웁니다.
- 그 밖의 항목(점수, 거리 등)은 보내도 **읽지 않습니다**.

성공(200):

```json
{
  "ok": true,
  "entry": {
    "id": "k3J0x1Yp9QmA", "nickname": "영욱", "mode": "distance",
    "score": 15.62, "distanceM": 15.62, "airtimeS": 3.07, "verdict": "glide",
    "code": "P1...", "createdAt": "2026-11-13T12:00:00.000Z"
  },
  "rank": 3,
  "total": 120
}
```

- `score` 는 거리 모드에서 `distanceM`, 체공 모드에서 `airtimeS` 입니다.
- 코드, 모드, 닉네임이 모두 같은 등록이 이미 있으면 새로 넣지 않고 기존 기록을 돌려주며 `"duplicate": true` 가 붙습니다.
- 점수가 같으면 먼저 등록한 기록이 위입니다.

### `GET /api/leaderboard?mode=distance|airtime&limit=50`

```json
{ "ok": true, "mode": "distance", "entries": [ { "...": "entry 와 같은 모양" } ], "total": 120 }
```

- `limit` 기본 50, 최대 100.

### 오류

```json
{ "ok": false, "errors": ["공유 코드를 읽을 수 없습니다. ..."] }
```

| 상태 | 경우 |
| --- | --- |
| 400 | JSON 이 아님, 항목 누락, 읽을 수 없는 코드, 던지기 값이 없는 코드, 규칙 위반, 잘못된 모드나 닉네임 |
| 404 | 없는 주소 |
| 405 | 맞지 않는 요청 방식 |
| 408 | 본문을 10초 안에 다 보내지 않음 |
| 413 | 본문이 8 KB 초과 |
| 503 | 등록 요청이 몰려 대기열이 가득 참(잠시 뒤 재시도) |

`errors` 는 사용자에게 그대로 보여줄 수 있는 한국어 문장입니다.

## 조작 방지 방식

방법은 한 가지입니다. **서버는 입력만 받아 다시 계산합니다.**

1. 화면은 공유 코드(설계 + 던지기 값)만 보냅니다. 결과 값은 보내지 않고, 보내도 서버가 읽지 않습니다.
2. 서버가 코드를 풉니다(`decodeDesign`). 코드에는 검사값이 있어 한 글자만 달라도 거절됩니다.
3. 설계와 던지기 값이 규칙 안인지 검사합니다(`validateSubmission`): 접기 횟수, 각도 범위, 던지는 속도 2~16 m/s 등.
4. 화면과 같은 `evaluate` 로 비행을 다시 계산하고, **서버가 계산한 결과만** 저장합니다.

코드는 값을 일정 단위(길이 0.1 mm, 각도 0.1도, 속도 0.01 m/s)로 반올림해 담습니다.
화면도 코드로 바꿨다가 되돌린 값으로 계산해 보여주므로, 화면에 보인 기록과 서버 기록이 정확히 같습니다.
계산에는 무작위가 없어서 같은 입력이면 언제나 같은 결과가 나옵니다.

### 막지 못하는 것

- **최적 입력 자동 탐색**: 프로그램으로 설계와 던지기 값을 수없이 바꿔 가며 가장 좋은 조합을 찾아 등록하는 것. 규칙 안의 입력이므로 정상 기록으로 처리됩니다.
- **여러 닉네임 사용**: 로그인이 없으므로 한 사람이 닉네임을 바꿔 여러 번 등록할 수 있습니다. 남의 닉네임을 쓰는 것도 막지 않습니다.
- **남의 코드 그대로 등록**: 랭킹에 공개된 코드를 복사해 다른 닉네임으로 등록할 수 있습니다.
- 요청 횟수 제한, 로그인, 행동 분석은 넣지 않았습니다. 필요하면 앞단(프록시, CDN)에서 횟수 제한을 거는 것을 권합니다.

## 계산 비용 보호

`evaluate` 한 번에 CPU 를 최대 0.2초쯤 씁니다. 그동안 Node 는 다른 요청을 처리하지 못합니다.

- 등록 요청은 대기열에 넣어 **한 번에 하나씩** 계산합니다.
- 한 건을 끝낼 때마다 5 ms 쉬면서 밀린 요청을 받습니다. 랭킹 조회는 이때 바로 응답합니다.
- 처리 중 + 대기 중이 `MAX_QUEUE`(기본 20)를 넘으면 계산하지 않고 503 으로 거절합니다. 최악의 대기 시간은 약 4초입니다.
- 완전히 같은 등록(중복)은 계산 없이 바로 기존 기록을 돌려줍니다.

## 저장

- `DATA_FILE` 이 있으면 JSON 파일 하나에 저장합니다. 시작할 때 읽고, 기록이 추가될 때마다 임시 파일에 쓴 뒤 이름을 바꿉니다(쓰다가 꺼져도 파일이 깨지지 않습니다).
- 파일에는 물리 판 번호(`physics`)를 같이 적습니다. 시작할 때 파일의 번호가 지금의 core 와 다르면(번호가 없는 예전 파일 포함)
  모든 기록을 저장된 코드로 다시 계산해서 싣습니다. 예전 규칙의 점수와 새 규칙의 점수가 한 순위표에 섞이지 않게 하기 위해서입니다.
  더는 규칙에 맞지 않는 기록(예: 지금 한도보다 센 던지기)은 버리고, 원래 파일은 `<DATA_FILE>.physics-<번호>` 로 옆에 보관합니다.
  기록 한 줄에 0.1~0.2초쯤 걸리므로(같은 코드는 한 번만 계산) 기록이 많으면 판이 바뀐 뒤 처음 한 번은 켜지는 데 시간이 걸립니다.
- 모드마다 상위 5000건만 보관합니다. 한도 밖 기록은 저장하지 않습니다.
- 파일이 깨져 있으면 `.corrupt-시각` 이름으로 옮겨 두고 빈 상태로 시작합니다.
- 프로세스 하나가 파일 하나를 씁니다. 같은 파일로 서버를 여러 개 띄우지 마세요.

## 배포

- Node 22 가 도는 곳이면 어디든 됩니다(Railway, Render, Fly.io, 일반 서버 등). 시작 명령은 `npm run server` 입니다.
- 랭킹을 유지하려면 지워지지 않는 디스크를 붙이고 `DATA_FILE` 을 그 경로로 지정합니다.
- 인스턴스는 **1개**로 운영합니다(메모리와 파일 하나를 쓰는 구조).
- `CORS_ORIGIN` 에 화면이 올라간 주소를 넣습니다.
- 정적 화면은 **빌드할 때** 서버 주소가 필요합니다.

  ```bash
  VITE_API_URL=https://ranking.example.com npm run build
  ```

  `VITE_API_URL` 없이 빌드하면 랭킹 기능이 숨겨지고 내 기록만 보입니다.
- 화면이 HTTPS 면 서버도 HTTPS 여야 합니다(브라우저가 섞인 요청을 막습니다).
- core 를 고쳐 계산 결과가 달라지면 예전 기록과 새 기록의 기준이 달라집니다. 그때는 랭킹 파일을 새로 시작하세요.

## 테스트

```bash
npx vitest run tests/server.test.ts
```

실제 HTTP 로 임시 포트에 서버를 띄워 확인합니다: 정상 등록, 서버 재계산 일치, 가짜 점수 무시, 변조 코드 거절, 범위 밖 던지기 거절, 본문 크기 제한, 엉터리 입력, 중복, 순서, CORS, 대기열, 파일 저장.
